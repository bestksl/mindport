# ADR-0006：入港即立箱——取消独立闪念/inbox

日期：2026-10-26
状态：已接受（v0.5 实现）
取代：ADR-0003 中「thought 类型 + inbox/ + `port promote`」的两段式捕获

## 背景

v0.3/v0.4 的捕获分两段：念头先进 `inbox/`（无编号的 thought），人再手动
`port promote` 成任务（草稿）。实际使用中用户明确反馈：

> 闪念就是入港的就行了，不用单独搞个闪念。

两段式带来的全是成本，没有换来清晰度：

1. **手机上多一步操作**：入港后还要在看板底部找到闪念、点「转集装箱」；
2. **看板信息分裂**：同一件事在「闪念·待澄清」和「草稿·备货中」两个区域表达；
3. **概念负担**：thought / task 两种类型、inbox / tasks 两个目录、promote 一条命令，
   而闪念和草稿的唯一差别只是「有没有 T 编号」。

草稿（draft）本来就是「备货中、船看不到、可随意打磨」的状态，天然承载捕获语义。

## 决策

1. **入港即立箱**：网页输入框与 `port add` 直接创建 draft 任务，立即占 T 编号。
   原念头文本进任务标题与「描述」，后续补验收标准、放行、派船的路径不变。
2. **删除整条闪念链路**：`AddThought` / `ListThoughts` / `PromoteThought`、
   `port inbox` / `port promote`、网页闪念区与 `/thoughts*` 路由、inbox CSS。
   `Meta.Type` 保留字段，历史 thought 文件的解析能力不影响（不再扫描该目录）。
3. **一次性迁移**：`port migrate-inbox` 把旧 `inbox/*.md` 按捕获时间顺序批量立箱
   为 draft（占新 T 编号），原件移入 `archive/inbox-legacy/`，不删除；可重复执行。
4. Vault 初始化不再创建 `inbox/` 目录。

## 后果

- 手机端：输入 → 入港 → 草稿卡出现，一步完成；看板只剩「草稿 + 四列」。
- T 编号消耗变快（每条捕获即占号），这是可接受的——编号只要求单调，不要求连续好看。
- 旧 vault 升级必须跑一次 `port migrate-inbox`（部署脚本在停服后、起服前执行）。
