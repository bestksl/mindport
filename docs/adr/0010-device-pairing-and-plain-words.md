# ADR-0010 设备配对与大众话术：一次性配对码、设备级会话、去航海化文案

- 状态：Accepted（2026-11-03）
- 接续：[ADR-0008](0008-session-transcript-bridge.md)（会话页与 transcript 桥接）、
  [ADR-0005](0005-harbor-dispatch.md)（定向指派模型）、
  [ADR-0009](0009-fleet-is-session.md)（船队即会话）

## 背景

两个独立问题同期处理。

**一、远程访问的准入方式太粗。** v0.4 起 `serve --auth` 只有一把共享密钥
（`web.token`），浏览器登录后把密钥本体写进 `mp_key` cookie，30 天有效：
换机、丢手机、cookie 泄露都只能换全局密钥，所有设备同时失效；手机输入 64 位
hex 密钥的体验也很差。调研 t3code 的连接方式后确认，行业主流做法是
「短期一次性配对码 → 交换成该设备独立长期会话凭证 → 可单独吊销」。

**二、港口业务隐喻增加理解成本。** 思港自 v0.4 建立了一套完整航海话术
（派船/锚地/船队/船位/接令/归港/验货/调度长官……）。视觉上的像素海港
（灯塔、货轮动画、夜港/日港/深海/青瓷四主题）广受喜欢，但**业务概念**
对新用户不友好：一眼看不出「派船」「验货」是什么。用户决定：皮肤保留，
业务说法换成任务软件的大众词汇。

## 结论

### 1. 一次性配对码 + 设备级会话

- `port pair` 在 serve 所在电脑上生成 **8 位配对码**（字母表
  `23456789ABCDEFGHJKLMNPQRSTUVWXYZ`，去除易混字符；crypto/rand 拒绝采样），
  **10 分钟过期、只能使用一次**。盘上只存 SHA-256 哈希，明文只出现在终端。
- 终端直接渲染二维码（skip2/go-qrcode，ANSI 半块字符），同时打印多条
  配对 URL（组网地址、局域网地址各一条，哪条通扫哪条）。配对码经
  **URL fragment**（`/pair#code=XXXX`）传递，不进服务端访问日志；
  落地页 JS 取出后 POST `/api/pair` 换取会话。
- 交换成功后签发**设备级会话**：随机 64-hex id 存 `mp_sid` cookie
  （HttpOnly、SameSite=Lax、30 天滑动续期），会话元数据（设备名取自 UA、
  来源 IP、创建/最近活跃时间）按设备一文件存
  `.port/state/web-sessions/<id>.json`，0700 目录。
- `port devices` 列出全部设备，`port devices revoke <id前缀>` **单独吊销**
  一台，不影响其他设备；登出只吊销当前设备。
- 安全细节：错码不消耗好码（只有成功才标记 used）；登录与配对按 IP 限频
  （每分钟 10 次，本机豁免）；共享密钥登录路径保留（`/login`），登录成功
  同样签发设备会话，浏览器不再保存密钥本体；旧版 `mp_key=<密钥>` cookie
  继续兼容放行，自然淘汰，不强制登出。
- **不做** t3code 的 DPoP、云中继、RFC 8693 token exchange：单用户本地优先
  模型不需要，设备会话 + 网络边界已足够。

### 2. 网络地址品牌中立

- serve 启动横幅把本机可达地址分成两类标注：**组网地址**（默认路由网卡之外、
  具备全局单播 IPv4 的虚拟网卡，蒲公英/ZeroTier/WireGuard 等都落这一类）
  与**局域网地址**（默认路由网卡 IP）。产品代码与 UI 中**不出现任何组网品牌名**，
  用户用什么组网都成立。

### 3. 业务词汇大众化，视觉皮肤不动

- 话术对照（用户可见处全部替换；历史 ADR 保留当时用词不改写）：

  | 旧 | 新 |
  |---|---|
  | 派船/派活/派令 | 指派/交给 |
  | 锚地 | 待办区（状态标签「待办」） |
  | 待接令/接令/领单 | 待领取/领取 |
  | 船队 | 会话（拟人语境称「助手」） |
  | 船位 | 工作目录/项目目录 |
  | 归港/出港中/出海 | 完成/进行中 |
  | 会话「待命」（idle） | 空闲 |
  | 点卯/报到/心跳（UI） | 在线/上线/在线状态 |
  | 调度台/调度长官 | 任务台/你 |
  | 验货 | 验收 |
  | 货/票货/集装箱 | 任务 |
  | 放行（草稿） | 发布 |
  | 打磨（任务单） | 编辑/完善 |
  | 点名（助手/工作目录） | 指定 |
  | 信箱 | 留言 |
  | 入港（捕获）/入港证 | 记下/访问密钥 |
  | 航线 | 目标 |
  | 拆船/船台/船名 | 删除会话/会话页/会话名 |

  > 修订（同日第二轮）：首轮把 anchored 译成「待命区/待命中」，用户指出
  > 「待命」仍是自造词、与主流任务软件对不齐。终稿按 Todoist/Things/Linear
  > 的 backlog 习惯改为**待办区/待办**；会话 idle 态按 Slack/飞书习惯叫
  > **空闲**，两个概念不再共用一个词。同步把「放行/打磨/点名」换成
  > 「发布/编辑/指定」。

- **保留**：产品名思港 MindPort 与 `port` 命令名；像素灯塔、集装箱货轮动画、
  ⚓⛵🚢 emoji、四套港口主题名（夜港/日港/深海/青瓷）；英文标识符
  （fleet/berth/dispatch/anchored……）、状态字符串值、URL 与命令名一律不变，
  迁移零数据成本。
- ADR 是决策历史：0005/0009 等旧文不改写，索引加术语变迁指引。

## 后果

- 手机接入从「抄 64 位密钥」变成「扫一次码」，丢设备可单独吊销。
- 新用户看到的是任务/助手/工作目录这套通用心智，港口只作为视觉风格存在。
- 配对与会话数据都在 `.port/state/`（运行时状态，不进 git 同步）。
