# ADR-0004：草稿/发布模型与执行者在线心跳

日期：2026-10-25
状态：已接受（v0.3 实现）

## 背景

v0.2 中网页身份只是自我声明的 cookie，任何身份打开详情页都能一键「领取/归港」，
发布者（人）在手机上浏览时会误触把任务领走又归港。同时人与 agent 在思港中的
角色没有区分：人应当是**发布者**（澄清念头、打磨验收标准、决定重要程度与指派），
agent 应当是**执行者**（领取已发布任务、推进、归港）。页面也无法显示
「Claude Code 此刻在不在线、正在干哪个任务」。

## 决策

### 1. 任务新增 draft 状态

状态机扩展为：

```
draft ──publish──▶ ready ──claim──▶ in_progress ──done──▶ done
                       ▲                │  ▲
                       │                └──unblock── blocked
                       └── 指派（assignee）随 publish 携带
```

- **draft（草稿·打磨中）**：网页建任务的默认状态。不可领取、不进 `port next`、
  不出现在待领取列；在看板独立的草稿区展示，可反复编辑正文与验收标准。
- **publish**：人显式发布，可同时携带 `assignee`（委派）。被指派任务仍是
  ready——委派表达「期望谁来」，执行者仍需显式 claim 接走，pull 模型不变。
- CLI 的 `port new` 默认直接发布（命令行是有意为之的快速入口），
  `--draft` 进入打磨流。

### 2. 在线心跳是运行时状态，不是任务数据

- 心跳文件存 `.port/state/agents/<actor>.json`（actor/任务号/状态行/时间戳），
  与任务内容分离；该目录不参与未来的 git 同步。
- TTL 2 分钟：mtime 在窗口内即在线，超时自动灰显，无需显式下线，崩溃自愈。
- 相同内容 20 秒防抖：钩子可以高频调用而不产生写放大。
- 页面每 20 秒轮询 `GET /api/agents` 本地渲染，**不走 SSE**：在线灯的变化频率
  不应触发整页 reload（SSE 仍只负责任务数据变化）。
- `claim` 成功后 store 层自动 `Present(actor, task, "")`；`done` 后自动清任务号。
  CLI 与网页两条入口共享同一行为。
- CLI：`port present [T编号] [--note ...]`、`port away`。

### 3. Claude Code 用会话钩子自动报到

项目 `.claude/settings.json` 配置：

- `SessionStart` / `UserPromptSubmit` → `port present --by claude@studio`
  （防抖使每次提问只在状态变化时写盘）；
- `Stop` → `port away`。

任务号由 claim/done 自动维护，钩子不需要理解任务上下文。

### 4. 误触防护

归港、受阻上浮、发布出港等不可逆/语义强烈的表单按钮带 `data-confirm`，
浏览器原生确认后才提交；勾选验收这种可逆操作不加确认。

## 后果

- 手机上「看着像可点的按钮但点了就真生效」的事故面被收敛到确认弹层之后；
- 草稿让「先记下来、以后再想清楚」与正式任务同构，不需要第三种载体；
- 心跳是 best-effort 本地状态：TTL 方案不保证精确在线，但零运维、无中心进程，
  与「文件即数据库、单二进制」的总架构一致；
- 已知限制：网页身份仍是自声明 cookie，局域网零鉴权（见 ADR-0001 与
  docs/ops.md 的暴露面说明），在引入真正鉴权前，发布/领取操作不做身份强制。
